**Тема:** Разработка поискового робота (краулера)  
**Дисциплина:** Информационный поиск  

---

## 1. Задание и требования к реализации

1. **Поисковый робот** — компонент обкачки документов на языке Python.
2. **Аргументы запуска:** единственным аргументом поисковому роботу подается путь до YAML-конфига (`config.yaml`), содержащий:
   - секцию `db` с параметрами базы данных;
   - секцию `logic` с задержкой между обкачкой (`delay_seconds`) и другими параметрами робота.
3. **Хранилище документов:** сохранение в базе данных документов со следующими обязательными полями:
   - `url` — нормализованный URL;
   - `html` — «сырой» HTML-текст документа;
   - `source` — название источника;
   - `fetched_at` — дата обкачки документа в формате Unix timestamp.
4. **Остановка и возобновление:** робота можно остановить в любой момент (Ctrl+C). При повторном запуске он продолжает обкачку с того документа, на котором остановился.
5. **Периодическая переобкачка:** робот периодически проверяет документы, уже сохраненные в базе, но обновляет их только в том случае, если содержимое страницы действительно изменилось.

## 3. Выполнение требований

### 3.1. Единственный аргумент — YAML-конфиг
Робот запускается командой:
```bash
python3 robot.py config.yaml
```
Файл `config.yaml` содержит:
- **Секцию `db`:** путь к базе данных SQLite (`path: robot.db`).
- **Секцию `logic`:** 
  - `delay_seconds: 0.25` — пауза между запросами;
  - `recrawl_after_seconds: 604800` — интервал переобкачки (раз в 7 дней);
  - `max_pages: 5000` — лимит страниц;
  - `sources` — список источников с seed-ссылками, разрешенными доменами и префиксами.

### 3.2. Структура сохраняемых документов в БД
Таблица `docs` в SQLite (`robot.db`) хранит все обязательные поля:
- `url` (TEXT PRIMARY KEY) — нормализованный адрес страницы;
- `html` (TEXT) — полный «сырой» HTML-код документа;
- `source` (TEXT) — источник (`wikipedia_en` или `spaceflightnow`);
- `fetched_at` (INTEGER) — дата обкачки в формате Unix timestamp.

Для поддержки условной переобкачки также сохраняются:
- `last_checked_at` — время последней проверки;
- `etag` и `last_modified` — заголовки сервера для условного GET;
- `content_hash` — хеш SHA-256 тела страницы;
- `http_status` — статус-код ответа сервера (200).

### 3.3. Остановка в любой момент и продолжение работы
- База данных очереди (`frontier`) сохраняет состояние каждого URL и запланированное время обкачки (`next_fetch_at`).
- Обработаны сигналы завершения (`SIGINT` / `Ctrl+C`). При прерывании транзакция фиксируется (`commit`).
- При перезапуске робот запрашивает из очереди URL с минимальным `next_fetch_at`. Уже обкачанные страницы перенесены на дату будущей переобкачки, поэтому робот автоматически подхватывает работу ровно с того места, где был остановлен.

### 3.4. Периодическая переобкачка только изменившихся документов
- При наступлении срока переобкачки робот извлекает метаданные документа (`etag`, `last_modified`, `content_hash`).
- Выполняется **Conditional GET**:
  - Отправляются заголовки `If-None-Match` и `If-Modified-Since`.
  - Если сервер вернул **HTTP 304 Not Modified**, тело не скачивается, в базе обновляется только время проверки `last_checked_at`.
  - Если сервер вернул HTTP 200, но вычисленный `sha256(html)` совпал с сохраненным `content_hash`, документ считается неизменившимся и не перезаписывается.
  - Только если контент действительно изменился, в таблице `docs` обновляются `html`, `fetched_at`, новый хеш и новые заголовки кэширования.

## 4. Как запускать

Все команды выполняются из каталога `lab 2`:

```bash
cd "lab 2"

# 1. Запуск робота с единственным аргументом — путем к yaml-конфигу:
python3 robot.py config.yaml

# 2. Либо запуск через main.py (по умолчанию берет config.yaml):
python3 main.py

# 3. Просмотр текущей статистики базы данных:
python3 main.py --stats
```
